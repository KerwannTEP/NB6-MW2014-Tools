# NB6-MW2014-Tools
Tools related to running NBODY6++GPU with MWPotential2014. 

## Description

This repository gathers tools to compile and run `NBODY6++GPU` (available [here](https://github.com/KerwannTEP/Nbody6ppGPU)) subject to the Milky-Way potential model `MWPotential2014` ([Bovy 2015](https://ui.adsabs.harvard.edu/abs/2015ApJS..216...29B/abstract)). It also provides tools to read the binary outputs and plot the cluster evolution in the galacticocentric frame.

Its primary purpose is to serve as comparison with KRIOS (available [here](https://github.com/UNC-Dynamics/KRIOS) soon) runs described in [Cook et al. (2026)](https://ui.adsabs.harvard.edu/abs/2026arXiv260213385C/abstract), but it may be of use to everyone wishing to study stellar streams.

This repository makes use of the Julia Language  (see [Bezanson et al. 2017](https://doi.org/10.1137/141000671)), whose repository is located at [JuliaLang](https://github.com/JuliaLang/julia/tree/master). To install Julia, the user may follow the instructions at [julialang.org/downloads/](https://julialang.org/downloads/).

## Compilation

We provide a SLURM script to compile our modified version of `NBODY6++GPU`. It can be found in the folder `job_slurm_nbody6pp/` under the name `job_compile_gpu.sh`. The user has to perform the following actions:

- Adapt the SLURM commands in the header accordingly.
- Indicate the path to the folder `Nbody6ppGPU` in the `PREFIX` variable.
- Indicate the path to the folder in which to install the executable in the `INSTALLPATH` variable.


## Running a simulation

We also provide a SLURM script to run our modified version of `NBODY6++GPU`. It can be found in the folder `job_slurm_nbody6pp/` under the name `job_run.sh`. The user has to perform the following actions:

- Adapt the SLURM commands in the header accordingly.
- Indicate the path to the binary file `nbody6++.avx.gpu.hdf5` in the `NBODY` variable,
- Indicate the path to the input file in the `INPUT` variable.
- Indicate the path to the folder for the run's outputs in the `PREFIX` variable.
- Indicate the path to the folder containing the initial conditions in the `IC` variable.

We provide an example of input file in the `input` folder, under the name `N_10000_MW2014.input`. We refer to Appendix B.2 of [Cook et al. (2026)](https://ui.adsabs.harvard.edu/abs/2026arXiv260213385C/abstract) for more details on the format of the input file, as well as the [official documentation](https://overleaf.com/project/61a0b9dc74d7e9276e99ea39).

We provide in the `scripts/` folder a `Julia` script, named `ConvertToDat10.jl`, to convert initial conditions generated with `cosmic` into the `NBODY6++GPU` format. The user should modify the lines for the `namefile` (path to the `cosmic` ICs) and the `namefile_dat` (path to the `NBODY6++GPU` ICs) accordingly .


## Reading the simulation's outputs

We provide scripts to read the outputs generated by the simulation. 

The user should use the SLURM script `job_convert_data.sh`, found in the folder `job_slurm_nbody6pp/`, to convert the binary outputs from the simulations into readable outputs. The user has to perform the following actions:

- Adapt the SLURM commands in the header accordingly.
- Indicate the path to the `python` executable in the `PYTHON` variable.
- Indicate the path to the folder for the run's outputs in the `PREFIX` variable.
- Indicate the path to the `python` script `ReadNbodyOutput.py`, given in the `scripts/` folder, in the `SAVE` variable.

The readable outputs will be saved in the folder containing the initial binary outputs of the simulation.


## Plotting the cluster's evolution

We provide in the folder `scripts/` two `Julia` scripts:

- The script `PlotClusterOrbit.jl`, which plots the cluster's orbit and produces a GIF file of the streams. The user has to indicate the path to the data output folder in the variable `path_to_data`, and the path to the folder in which to save the figures and GIFs in the variable `path_to_plot`.
- The script `PostProcessing.jl`, which saves and plots a selection of relevant quantities, such as IOMs or Lagrange radii (see lines 565-606 for a complete description). The user should indicate the same paths as in the first script.
